## pioasm options used

- `pioasm -v <0|1> -o json <file.pio> <file.pio.json>` (all programs, instructions as 4-digit hex, pioVersion, wrap, side-set, clock divider, FIFO config)
- `pioasm -v <0|1> -o c-sdk <file.pio> <file.pio.c-sdk.h>` (wrap, side-set and clock config as the C SDK sees them)
- `pioasm -v <0|1> -o hex <file.pio> <out>`: run only for single-program files, as a cross-check. pioasm refuses `-o hex` for multi-program input.
- Multi-program files get `<file.pio>.<program>.hex`, derived from the JSON `instructions[].hex` values (one word per line, lowercase, 4 digits, the same layout as `-o hex`). The script checks that this derivation equals pioasm's own `-o hex` for every single-program file.
- `-v 0` (the pioasm default) is used unless a file needs PIO version 1, which then gets `-v 1` (see detection below). No other options are passed.

## PIO version detection

A file **uses PIO v1** if either:

1. it contains a `.pio_version 1` directive (`declared`), or
2. `pioasm -v 0` rejects it with `PIO version 1 is required for '...'` (`feature`). pioasm gates `mov pindirs`, `mov rxfifo[...]`, `wait ... jmppin`, `irq prev`/`irq next`, and `.fifo txput`/`txget`/`putget` this way.

Files that do not use v1 are assembled as PIO v0 (RP2040), which is Polyglot's base. v1 files are kept in the corpus but tracked separately.
