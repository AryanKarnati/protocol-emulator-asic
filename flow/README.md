# Pre-layout area and timing estimate

`flow/estimate.sh` runs Yosys and ABC on the generated Verilog of `pio_block1`, `pio_block`
and the Tiny Tapeout top, and prints area, flop count and the critical path of each. It is a
planning number for block 2, not a sign-off number.

## Usage

    flow/estimate.sh

Needs `yosys` (with the `abc` pass), `dune` and the `polyglot` opam switch. Set
`OPAM_EXEC="$HOME/.local/bin/opam exec --switch=polyglot --"` if `opam exec --` is not on
the default switch. Output goes to `flow/build/` (gitignored).

Inputs:

- `pio_block1` and `pio_block`: generated by `hw/bin/gen_verilog.exe` (engine.md section 8),
  4 SMs and 1 SM respectively. Both have the top module name `pio_block`.
- The TT top: `src/project.v` and `src/polyglot.v`, module `tt_um_aryankarnati_polyglot`. This
  is the block 1 gate design, because the block 2 top does not exist until block 3.
- Liberty: IHP `sg13g2_stdcell`, slow corner (`sg13g2_stdcell_slow_1p08V_125C.lib`) by
  default, typ with `CORNER=typ`. Cached in `~/.cache/polyglot/ihp/`. If a file is missing,
  the script fetches it from IHP-Open-PDK, but only when `IHP_PDK_COMMIT` is set to a pinned
  commit. It refuses to fetch without one.

## What runs

Area run (the orchestrator's first command):

    read_verilog X.v; synth -top TOP -flatten; dfflibmap -liberty L;
    abc -liberty L -D 15000; opt_clean; stat -liberty L

Timing run (the same synthesis, then the orchestrator's ABC script at `-D 16000`):

    abc -liberty L -D 16000 -script abc_timing.script

`abc_timing.script` holds the orchestrator's commands one per line. Yosys reads an inline
ABC script with `,` as the separator, and the orchestrator's `;` form failed on it. So the
commands go in a file, and `{D}` is the delay target, as in the orchestrator's string.

Reported: area from the area run (`stat`, `Chip area for module`), flop count (cells named
`sg13g2_df*` or `sg13g2_sdf*` in the same `stat`), and the critical path delay with its start
and end points from `stime -p` in the timing run.

## What the numbers mean

- **Area** is the sum of the mapped standard-cell areas after synthesis and ABC mapping, in
  µm² (shown in mm²). It is a cell-area estimate. It does not include routing, fill, the
  I/O ring, the power grid, or the utilisation factor a placed design needs.
- **Flops** is the number of sequential cells after `dfflibmap`. A latch-based design would be
  counted differently, but this design has none.
- **Delay** is the longest combinational path that ABC can see, with the `stime` model at the
  chosen corner. Start and end are the ABC pin names, such as `pi230 (\clkdiv0 [17])` for a
  primary input and `po1107 (\_413 [0])` for a primary output. These names are internal to
  the flattened netlist and do not match RTL signal names directly.
- The ABC delay target (`-D`) makes ABC optimise for speed, so the reported delay is close
  to the target when the logic can reach it. It is not a guarantee.

## What the numbers do not mean

- **No wire load.** `stime` uses `WireLoad = "none"`. Real wires add delay, more on the long
  nets that run from the register files to the output muxes. Expect the post-layout delay
  to be higher.
- **No clock tree.** The clock is treated as ideal. Skew, insertion delay and clock buffers
  are not modelled, so flop-to-flop slack is optimistic by the skew.
- **No placement or routing.** Area is cell area only, and there is no congestion or
  density model.
- **No IO timing.** Pads, the I/O constraints of the Tiny Tapeout harness, and the input and
  output delays set by the testbench are not modelled.
- **No hold analysis and no corner sweep.** Only one corner is run per invocation.
- **Yosys and ABC are not the flow Tiny Tapeout uses.** The sign-off run is the Tiny Tapeout
  GDS action (OpenROAD). Its numbers will differ, and they are the ones that count.
- **Different RTL, different numbers.** The orchestrator's earlier figures (0.149 mm² and 9.2 ns
  for `pio_block1`, at RTL 72727ee) do not match this run. Compare only numbers from the same
  RTL and the same script.
